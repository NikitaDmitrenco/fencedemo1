# План создания демо-сайта «Заборы и ворота»

Рабочий план разработки универсального одностраничного демо для ниши «Заборы, ворота и
металлоконструкции». Основан на [ТЗ](./TZ.md). Документ — руководство к реализации: что делаем,
в каком порядке, по каким правилам и как проверяем результат.

---

## 0. Краткая формула продукта

> **Продаём не сайт — продаём следующий шаг: расчёт объекта посетителя.**

Всё в проекте подчинено одной метрике: **доля посетителей, дошедших до отправки контакта**
(квиз, мини-форма или звонок). Любой элемент, который не работает на эту метрику или на доверие,
которое её обеспечивает, — из сборки убирается.

Два уровня цели:

| Уровень | Аудитория | Что должно произойти |
|---|---|---|
| **Демо** | владелец компании по заборам | за 30–60 сек без пояснений понимает: «мой бизнес мог бы выглядеть так же» → пишет нам |
| **Боевая версия** | клиент этой компании | за 1 сессию доходит от «сколько стоит» до отправки телефона на расчёт |

Из этого следует главное архитектурное требование: **сайт-конструктор**. Один код — любой клиент.
Замена под нового заказчика = правка одного конфиг-файла + папка с фото + один акцентный цвет.

## 1. Технологический стек

| Слой | Решение | Почему именно так |
|---|---|---|
| Фреймворк | **Next.js 16 (App Router) + TypeScript** | SSG/ISR из коробки, нативный деплой на Vercel, готовая база для будущих `/services`, `/projects`, `/prices` без переделки |
| Стили | **Tailwind CSS v4 + CSS-переменные для темы** | скорость сборки блоков + перекрас под фирменный цвет клиента через одну переменную |
| Типографика | `next/font` (Manrope / Inter Tight), self-hosted | без запросов к сторонним CDN, нулевой CLS |
| Изображения | `next/image`, AVIF + WebP, `sizes`, blur-placeholder | требование ТЗ по WebP/AVIF и lazy-load |
| Анимации | CSS-transitions + IntersectionObserver reveal | «короткие micro-interactions» без тяжёлых библиотек и параллаксов |
| Формы/лиды | Route Handler `/api/lead` → Telegram Bot API (+ опционально e-mail через Resend) | мгновенная доставка заявки владельцу, без бэкенда и без платных сервисов |
| Валидация | `zod` на клиенте и на сервере | одна схема, защита от мусорных заявок |
| Аналитика | Яндекс.Метрика (вебвизор + цели) + Vercel Analytics | требование ТЗ; цели на каждый шаг воронки |
| Хостинг | **Vercel** (Hobby/Pro), домен + HTTPS автоматически | требование ТЗ по домену/HTTPS, нулевой DevOps |
| Качество | ESLint + Prettier + `@next/bundle-analyzer` + Lighthouse CI | контроль мобильной скорости, которая в ТЗ вынесена в отдельное требование |

**Сознательно НЕ берём:** CMS (избыточно для 25 000 ₽ и замедляет тиражирование), Framer Motion /
GSAP (вес ради эффекта), UI-киты вроде MUI (чужая визуальная эстетика — прямо против ТЗ),
внешние конструкторы квизов (реклама чужого бренда и лишние 200 КБ JS).

│  ├─ pricing.ts              # матрица цен и коэффициентов для калькулятора

├─ public/
│  ├─ media/demo/             # фото демо-версии
│  └─ media/<client-slug>/    # фото конкретного клиента
├─ docs/
│  ├─ TZ.md                   # исходное ТЗ
│  ├─ PLAN.md                 # этот документ
│  └─ HANDOFF.md              # инструкция «как перекрасить демо под клиента за 40 минут»

**Правило секций.** Каждая секция — самодостаточный компонент, который принимает данные из
`site.config.ts` и ничего не знает о соседях. Порядок секций задан массивом в `page.tsx`:
перестановка блоков под конкретного клиента — это перестановка строк в массиве, а не рефакторинг.

## 3. Контентная модель — механизм тиражирования

Ядро экономики продукта. Всё, что различается у двух клиентов, вынесено в `content/site.config.ts`:

```ts
export const site: SiteConfig = {
  company: { name, legalName, inn, phone, whatsapp, telegram, address, geo, workHours },
  brand:   { accent: '#E0A33C', logo: '/media/<client>/logo.svg', photoDir: '/media/<client>' },
  hero:    { title, subtitle, proofs: [4 пункта], image },
  products:[ { slug, title, benefit, priceFrom, image } ],   // 4–5 карточек
  cases:   [ { title, type, length, height, gates, term, price, district, photos[] } ],
  estimate:[ { item, note } ],                                // состав сметы
  durability:[ { title, text } ],                             // 4–5 факторов срока службы
  process: [ 6 шагов ],
  trust:   { years, objects, crews, production, warranty, contract, owner },
  reviews: [ { author, source: 'yandex'|'2gis', text, url, date } ],
  faq:     [ 5–7 вопросов ],
  legal:   { privacyUrl, consentUrl, requisites },
};
```

Три правила, вытекающие прямо из ТЗ:

1. **Все недоказанные цифры в демо — `[X]`.** Тип поля допускает литерал `'[X]'`, поэтому
   «15 лет на рынке» физически невозможно случайно оставить в демо-версии как факт.
2. **Отзывы только с источником.** Поле `url` обязательное — карточка отзыва без ссылки на
   оригинал не собирается (ошибка типизации). Никаких «Иван Иванов» и сгенерированных аватаров.
3. **Обещания на условной логике.** Блок «фиксируем смету договором» рендерится, только если
   `trust.contract === true`. Не обещаем за клиента то, чего он не делает.

**Перекраска под нового клиента** (цель — ≤ 40 минут, описано в `docs/HANDOFF.md`):
`brand.accent` → 1 строка · логотип → 1 файл · фото → 1 папка · факты/цены/кейсы/отзывы →
один конфиг · телефон и мессенджеры → один объект. Кода не касаемся вообще.

## 4. Дизайн-система

### Палитра (графит / молочный / металл + ровно один акцент)

| Токен | Значение | Применение |
|---|---|---|
| `--ink` | `#14181B` графит | основной текст, тёмные секции, футер |
| `--ink-soft` | `#3A4247` | вторичный текст |
| `--paper` | `#F7F5F2` молочный | фон страницы |
| `--steel` | `#8B9399` / `#D9DCDE` | металл: линии, подложки, границы 1 px |
| `--accent` | `#E0A33C` янтарный (переменная!) | **только** CTA, активные шаги квиза, цена «от» |
| `--ok` / `--warn` | служебные | статусы форм, ничего декоративного |

Акцент — единственный. Он же — точка индивидуализации: у клиента с синим фирменным стилем меняется
одна переменная, и весь сайт перестраивается без правок компонентов.

### Типографика и ритм

- Заголовки: `clamp(2rem, 1.2rem + 3.2vw, 4.25rem)`, tight-tracking, вес 700.
- Body 17–18 px, line-height 1.6, длина строки ≤ 68 символов.
- Сетка 4 pt; вертикальные отступы секций: 64 px mobile / 120 px desktop — «много воздуха» из ТЗ.
- Радиусы 14–16 px, границы `1px solid var(--steel-line)`, тени — максимум одна мягкая на карточке
  в hover. Никаких многослойных теней и рамок поверх рамок.

### Micro-interactions (бюджет — строго)

Hover карточки: подъём 2 px + смена границы, 150 ms `ease-out` · Кнопка: сдвиг иконки 2 px ·
Появление секции: `opacity 0→1` + `translateY 12px→0`, один раз, через IntersectionObserver ·
Квиз: смена шага 180 ms · Аккордеон: высота 200 ms.
`@media (prefers-reduced-motion: reduce)` отключает всё перечисленное. Параллаксов нет.

### Фотография

Крупные кадры **готовых объектов целиком** (забор + дом + участок), а не металл макро и не стоковые
бригады в касках. Единая обработка: чуть приглушённая насыщенность, холодные тени — чтобы разные
съёмки клиента выглядели одной серией. Соотношения: hero 16:9 / 4:5 на мобиле, кейсы 3:2,
карточки продуктов 4:3.

## 5. Реализация секций (порядок = маршрут пользователя из ТЗ)

| # | Секция | Ключевые решения реализации |
|---|---|---|
| 1 | **Hero** | Полноширинное фото объекта, затемняющий градиент снизу, H1 «Заборы и ворота под ключ» + подзаголовок «изготовление · доставка · монтаж». Две кнопки: primary «Рассчитать стоимость» (скролл к квизу), ghost «Посмотреть работы». Под ними — строка из 4 пруфов (гарантия / своё производство / монтаж / договор) иконками без рамок. Меню — 4 якоря + телефон, на мобиле сворачивается. Hero-фото грузится с `priority`, всё ниже — lazy |
| 2 | **Квиз** | 5 шагов: тип → длина → высота → ворота → контакт. Один вопрос на экран на мобиле, крупные тап-таргеты ≥ 56 px, прогресс-бар и «Назад». Ответы — карточки с картинкой, не радиокнопки. На шаге 5 — предварительный **диапазон** цены, посчитанный на клиенте, и поле телефона. Состояние — `useReducer`, черновик в `sessionStorage` (вернулся — не потерял) |
| 3 | **Каталог решений** | 4–5 карточек (профнастил, евроштакетник, 3D-сетка, жалюзи, откатные ворота): фото, одна строка пользы, «от N ₽/м.п.», CTA «Рассчитать» — открывает квиз с **предзаполненным типом**. Никаких таблиц характеристик |
| 4 | **Кейсы** | Карточка = слайдер 3–5 фото + строка параметров: тип · длина · высота · ворота · срок · стоимость · район. Именно параметры делают кейс доказательством, а не галереей. На десктопе 2 колонки, на мобиле — горизонтальный snap-scroll. Лайтбокс на чистом CSS-диалоге |
| 5 | **Прозрачная цена** | Разбор сметы на 7 позиций (материал, столбы/лаги, ворота, автоматика, доставка, монтаж, допработы) — визуально как чек с подытогами. Явный дисклеймер «точная цена — после замера» + CTA. Блок «фиксируем договором» — условный |
| 6 | **Срок службы** | 5 карточек-факторов (толщина металла, каркас, антикор, способ монтажа, фундамент ворот) в формате «как делают дёшево → что это значит через 3 года → как делаем мы». Это блок отстройки от «у кого метр дешевле» |
| 7 | **Этапы работы** | 6 шагов. Desktop — горизонтальная линия с нумерацией, mobile — вертикальный таймлайн. Каждый шаг с ответом «сколько это занимает» |
| 8 | **Почему доверяют** | Счётчики фактов (годы / объекты / бригады / гарантия), в демо — `[X]`. Фото владельца или команды + 2–3 предложения от первого лица. Именно живое фото отличает сайт от шаблона |
| 9 | **Отзывы** | 2–4 развёрнутых отзыва с бейджем источника (Яндекс Карты / 2ГИС), датой и ссылкой на оригинал. Аватары — только реальные или инициалы на плашке |
| 10 | **FAQ** | Аккордеон `<details>`-семантики, 5–7 вопросов: цена без замера, сроки, предоплата, ворота отдельно, география, гарантия, сезон/грунт. Ответы по 2–4 строки. Размечается FAQPage-схемой |
| 11 | **Финальный CTA + контакты** | Мини-форма из 3 полей: что нужно · примерная длина · телефон + чекбокс согласия. Ниже — телефон, WhatsApp/Telegram, адрес, география работ, реквизиты, ссылки на политику и согласие |
| — | **Sticky CTA (mobile)** | Фиксированная нижняя панель «Позвонить \| Рассчитать» с `env(safe-area-inset-bottom)`. Появляется после прохождения hero, прячется при открытой форме |

## 6. Квиз и логика предварительного расчёта

Квиз — главный конверсионный механизм, поэтому описан отдельно.

**Шаги:** `type` (профнастил / евроштакетник / 3D-сетка / жалюзи / только ворота / комплект) →
`length` (пресеты 20/30/50/80 м + своё значение) → `height` (1.5 / 1.8 / 2.0 / 2.5 м) →
`gates` (откатные / распашные / калитка / не нужны, + автоматика) → `contact`.

**Расчёт** (чистая функция в `content/pricing.ts`, без обращений к серверу):

```
базовая = цена_за_метр[тип] × коэффициент_высоты × длина
ворота   = цена_ворот[тип] + (автоматика ? цена_автоматики : 0)
итого    = базовая + ворота
диапазон = [итого × 0.9, итого × 1.15]   → округление до 1 000 ₽
```

Показываем **диапазон**, а не точную сумму, и подписываем: «предварительно, без замера». Это
требование ТЗ (снятие страха «сказали одно — стало вдвое») и одновременно юридическая защита.

**Конверсионные детали:** контакт спрашивается последним, когда вовлечение уже создано ·
результат показывается **до** запроса телефона, а не в обмен на него (телефон — за «точный расчёт
и выезд замерщика») · выбор мессенджера вместо звонка · маска `+7 (___) ___-__-__` · honeypot-поле
и rate-limit по IP · заявка уходит в Telegram владельцу за секунды с полной разбивкой ответов.

## 7. Производительность, SEO, доступность, право

**Бюджет скорости** (mobile, 4G, Lighthouse):
LCP ≤ 2.0 с · CLS ≤ 0.05 · INP ≤ 200 мс · JS на первый экран ≤ 120 КБ gzip ·
Performance / Accessibility / Best Practices / SEO ≥ 95.
Средства: SSG, серверные компоненты для всего статичного, `'use client'` только в квизе / формах /
аккордеоне / слайдере, AVIF+WebP с явными `sizes`, self-hosted шрифты, отложенная загрузка Метрики
после первого взаимодействия или `requestIdleCallback`.

**SEO базового уровня:** уникальные title/description из конфига, семантические `h1…h3`,
schema.org `LocalBusiness` + `Service` + `FAQPage` + `AggregateRating` (только при реальных отзывах),
OG/Twitter-картинка, `sitemap.xml`, `robots.txt`, canonical. Заделы под апгрейд: роутинг и данные
уже разложены так, что `/services/[slug]`, `/projects/[slug]`, `/prices` и региональные страницы
добавляются поверх существующего конфига без переписывания лендинга.

**Доступность:** контраст ≥ 4.5:1, фокус-кольца видимы, квиз проходится с клавиатуры,
`aria-live` на шагах и результате, alt у всех изображений, тап-таргеты ≥ 44 px.

**Юридический минимум (152-ФЗ):** обязательный чекбокс согласия во всех формах (не предустановлен),
страницы `/privacy` и `/consent`, cookie-баннер, реквизиты в футере. В демо — с явной пометкой
«шаблон, заменяется под юрлицо клиента».

## 9. Контроль качества перед отправкой демо

**Конверсия.** Кнопка «Рассчитать» видна на любом экране страницы · CTA один по смыслу на всём
сайте · до квиза можно дойти в один тап из любой точки · квиз проходится за ≤ 60 секунд ·
результат показывается до запроса телефона · заявка приходит в Telegram с полной разбивкой.

**Доверие.** Ни одной недоказанной цифры без `[X]` · каждый отзыв со ссылкой на оригинал ·
у кейсов указаны длина, высота, срок и стоимость · нет ни одного «мы профессионалы» без факта рядом.

**Визуал.** Ровно один акцентный цвет · нет зелёного «строительного» шаблона · нет стоковых
бригад в касках · тени и рамки не накладываются · анимации ≤ 200 мс и отключаются
по `prefers-reduced-motion`.

**Техника.** Lighthouse mobile ≥ 95 по всем четырём метрикам · проверено на iPhone SE (375 px) и
Android · sticky bar не перекрывает контент и учитывает safe-area · формы работают при выключенном
JS-автозаполнении · 404 и privacy на месте · HTTPS и домен подключены.

**Главный тест ТЗ.** Отправляем ссылку человеку не из проекта без единого слова пояснения.
Если за 30–60 секунд он говорит «понятно, это сайт компании по заборам, и вот тут считают цену» —
демо готово. Если требуется хоть одна фраза объяснения — переделываем первый экран.

## 10. Риски и решения

| Риск | Решение |
|---|---|
| Нет реальных фото объектов для демо | Единая лицензионно чистая подборка с ручной цветокоррекцией + пометка «фото заменяются на объекты вашей компании». Никаких коллажей из разных стилей |
| Демо примут за обман (выдуманные цифры) | Все факты — `[X]`, отзывы в демо помечены как образец. Заложено на уровне типов, а не дисциплины |
| Цены калькулятора не совпадут с реальными у клиента | Матрица цен вынесена в отдельный файл; всегда показывается диапазон с оговоркой «без замера» |
| Квиз утяжелит мобильную страницу | Квиз — единственный крупный клиентский компонент, грузится динамически при скролле к нему |
| Клиент попросит «ещё один акцентный цвет» | В `HANDOFF.md` зафиксировано правило одного акцента с объяснением, почему это продаёт лучше |
| Лид не дошёл (Telegram недоступен) | Дублирование на e-mail + запись в лог Vercel + явное сообщение об ошибке с телефоном для звонка |

## 12. Журнал решений

**Next.js 16 вместо 15.** На момент старта Э0 актуальный стабильный релиз — 16.3.5.
App Router, серверные компоненты и модель деплоя на Vercel не изменились, поэтому план
не затронут. React 19.3, Tailwind 4.3.

**Правовые страницы перенесены из Э5 в Э0.** `/privacy` и `/consent` нужны сразу: без них
нельзя показывать формы даже в демо. Тексты шаблонные и помечены как образец через `isDemo`.

**Reveal-анимация работает без состояния React.** Видимость переключается
атрибутом на DOM-узле: это чисто визуальный эффект, и ре-рендер каждого блока
страницы ради него не нужен. На случай выключенного JS в layout лежит
noscript-правило, снимающее скрытие.

**Аккордеон собран на нативных `<details>`.** Клавиатура, поиск по странице и
корректная семантика — без единого байта JavaScript в блоке FAQ, который есть
на каждом сайте этой серии.

**`docs/HANDOFF.md` написан на Э0, а не на Э5.** Инструкция описывает контентную модель,
а модель готова уже сейчас — писать её потом означало бы восстанавливать решения по памяти.
